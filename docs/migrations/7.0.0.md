# Upgrading to herogold 7.0.0

This note is for apps that use herogold 6.x and move to 7.0.0. Each section lists what changed, then shows the 6.x code and its 7.0.0 replacement.

## Binding the engine

In 6.x, importing the ORM read `db_config.ini` and created a module-level engine and session. In 7.0.0, importing the ORM does no file or database I/O. The app passes its own engine to the ORM.

Bind the engine once at startup:

```python
# 6.x: implicit, from db_config.ini on import
from herogold.orm import User

# 7.0.0: the app supplies the engine
from herogold import orm
from sqlalchemy import create_engine

orm.bind(create_engine("postgresql://app@localhost/app"))
```

In tests, use `bound` to bind an engine for one block and restore the previous binding after it:

```python
from herogold import orm

with orm.bound(test_engine):
    ...  # ORM calls here use test_engine
```

If you still keep settings in `db_config.ini`, build the URL from the file and pass it to `create_engine`:

```python
from pathlib import Path

from sqlalchemy import create_engine

from herogold import orm
from herogold.orm.core.constants import url_from_config

orm.bind(create_engine(url_from_config(Path("db_config.ini"))))
```

`url_from_config` creates the file with defaults if it is missing. It reads the file only when you call it.

An ORM call that needs an engine and finds none raises `herogold.orm.NoEngineBoundError`. The message says to call `herogold.orm.bind(engine)` first.

Removed names and their replacements:

- `Model.session` has no replacement. Pass a session to each call, or let the ORM open one.
- `SessionMixin` is removed. Remove it from your model bases.
- `herogold.orm.core.constants.engine` and `herogold.orm.core.constants.session` are removed. Call `orm.bind(engine)` instead.

## Commits

In 6.x, every ORM write committed the session it received. In 7.0.0, the ORM commits only a session it opened for the call itself. A session you pass is flushed, so ids are assigned, but the commit is yours. See [ADR 0001](../adr/0001-orm-commits-only-owned-sessions.md) for the reasoning.

```python
# 6.x: add() committed the session
user.add(session)

# 7.0.0: add() flushes the session. Commit it yourself.
with Session(engine) as session:
    user.add(session)
    session.commit()

# 7.0.0: without a session, the call opens and commits its own
user.add()
```

Group a signup, its links and its custom data in one session, and commit once at the end. A failure then rolls back all of them.

## Relationships

Class access now returns the `Relationship` descriptor. In 6.x it returned the target class. Use `target(owner)` to get the target class.

```python
# 6.x
Order.customer  # User

# 7.0.0
Order.customer  # the Relationship descriptor
Order.customer.target(Order)  # User
```

Instance access still returns the linked object or `None`.

The relationship verbs take a `session=` argument:

```python
# 6.x
order.customer = user

# 7.0.0
Order.customer.link(order, user, session=session)
Order.customer.get(order, session=session)
Order.customer.unlink(order, session=session)

# 7.0.0: assigning None also unlinks
order.customer = None
```

The query helpers build SQL for relationship lookups:

```python
Order.customer.is_set()                      # condition: the order has a customer
select(Order).where(Order.customer.is_set())
Order.customer.owners_of(user)               # query for the orders linked to user
Order.customer.targets_of(select(Order))     # query for the customers of those orders
Order.customer.link_table(Order)             # the association table
```

The `optional=` argument of `Relationship` is deprecated. Passing it emits a `DeprecationWarning` and has no effect. It is removed in 8.0.0. Remove it now.

```python
# 6.x
customer = Relationship(User, optional=False)

# 7.0.0
customer = Relationship(User)
```

## Custom data

`set_custom_data` replaces `CustomDataContainer` and stores the data in a session you pass.

```python
# 6.x
CustomDataContainer(item, data).set()

# 7.0.0
from herogold.orm import set_custom_data

set_custom_data(item, data, session=session)
```

The function flushes the session and does not commit it. A second call replaces the link instead of merging the data.

`validate_size` raises `OutOfSpaceError` when the data is too large. The check runs before anything is written. The size is the number of UTF-8 bytes in the compact JSON form of the data, with no spaces after separators. Nested values count in full.

```python
from herogold.orm.custom_data import OutOfSpaceError, validate_size

try:
    validate_size(data, limit=10_240)
except OutOfSpaceError:
    ...  # reject the payload
```

The FastAPI layer still returns HTTP 413 for an oversize payload.

## API

The FastAPI layer moved to a new module.

```python
# 6.x
from herogold.orm.core.api_model import APIModel

# 7.0.0
from herogold.orm.api import APIModel
```

Each request now gets one session from the `SessionDep` dependency. The session commits when the route returns and rolls back when it raises.

`CustomDataContainer` is removed. Use `set_custom_data`, shown above.

`Model.from_` returns a list. In 6.x it returned a `ScalarResult`, so callers called `.all()` on it.

```python
# 6.x
users = User.from_(User.email, "a@example.com").all()

# 7.0.0
users = User.from_(User.email, "a@example.com")
```

## Removed and renamed names

| 6.x name | 7.0.0 replacement |
| --- | --- |
| `Model.session` | Pass `session=`, or let the call open one |
| `SessionMixin` | Remove from model bases |
| `herogold.orm.core.constants.engine` | `herogold.orm.bind(engine)` |
| `herogold.orm.core.constants.session` | `herogold.orm.bind(engine)` |
| `herogold.orm.core.api_model` | `herogold.orm.api` |
| `CustomDataContainer` | `set_custom_data(item, data, session=...)` |
| `Relationship(..., optional=...)` | Deprecated, removed in 8.0.0 |
| `db_config.ini` read on import | `orm.bind(engine)`, or `url_from_config(path)` |
